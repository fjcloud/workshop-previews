Lab 2.1 — Launch Your Dev Space

Review preview — PR 32, not the published workshop. This page comes from commit ebcde0ef63f873d183a56da9f1e63c22ea373e71 on branch docs/aro-guided-workshop-pr-preview. Read the changes and leave feedback in the pull request. The production workshop on main is unchanged. The clone command in Act 0 uses this review branch so its proposed manifests can be reviewed together.

What you will do and why

Goal: Start the developer experience with the dev account. Open an isolated browser workspace containing the editor, CLI tools, model configuration and app template. You consume the platform built in Act 1; you do not install OpenShift AI, create a DataScienceCluster, or grant pod security permissions. This is the handoff from platform engineering to application development.

Welcome to Act 2. You are now the Developer. Everything you need — editor, terminal, and OpenCode pointed at DeepSeek-V4 Pro — is in the browser through OpenShift Dev Spaces. No laptop installation is required. The model is published through the OpenShift AI MaaS gateway prepared in Act 1.

Estimated time: 10 minutes
Persona: Developer
What you need: The platform prepared in Act 1 and your cluster login

What is OpenShift Dev Spaces?

OpenShift Dev Spaces provides cloud-based developer workspaces — VS Code-compatible IDEs that run as pods in the cluster. Key benefits:

  • Zero local setup: the workspace comes pre-configured; just open a browser

  • Consistent environment: every developer gets the same tools, versions, and configuration

  • Model access: the workspace calls MaaS at $OPENAI_BASE_URL with an injected MaaS key — same chat-completions JSON, pay per token

  • Persistent storage: your work survives closing the browser, but remains tied to the lifetime of this RHDP environment. Export anything you want to keep before it expires

Get the Dev Spaces URL

The models and runtime agent backend are now ready. In the bastion terminal, generate the workspace launch link:

Run in the bastion terminal: the existing browser terminal beside this guide in Cloud Terminal. Use the workshop checkout (~/aro-ai-app-platform). Stay signed in as workshop-admin for the platform labs; Act 0 explains the initial login.

 
# Read the operator-reported browser IDE URL for this cluster.
DEVSPACES_URL=$(oc get checluster devspaces -n openshift-operators -o jsonpath='{.status.cheURL}')
# Wait for all CPU-node image caches before launching the workspace.
oc rollout status daemonset/kubernetes-image-puller -n openshift-operators --timeout=600s
# Select the ARO template branch; it contains scaffolding and tests, not a finished app.
TEMPLATE_URL=https://github.com/fjcloud/go-app-template/tree/aro-card-scout
# Print the prepared browser launch URL; no credential is included.
printf '%s/#%s?ai-provider=opencodeai/opencode\n' "${DEVSPACES_URL%/}" "$TEMPLATE_URL"

Open the printed link in your browser. It clones the Card Scout template and creates the workspace from its devfile.yaml.

The #<template-url> suffix tells Dev Spaces to clone the template and create a workspace from its devfile.yaml automatically. OpenCode is injected by the platform. The project opencode.json already pins DeepSeek through MaaS. The workspace comes pre-loaded with a short AGENTS.md, APP_CONTRACT.md, acceptance tests, DELIVERY.md and the delivery scaffold — you only need to write the application code.

  1. Open that URL in your browser.

Switch to the developer account

Choose the workshop identity provider and sign in as dev with the developer password created in Act 0. The workshop catalog password is different. Use the separate developer browser profile/private window from Lab 1.7. If the browser logs you straight in as workshop-admin, sign out or change browser profile before creating a workspace. The project dev-devspaces is already prepared for dev. Keep the OpenShift password out of OpenCode and Git; the developer terminal receives its own scoped identity.

Log In and Create Your Workspace

  1. You will be redirected to OpenShift SSO. Choose workshop and log in as dev.

  2. On first access, click Log in with OpenShift if prompted, then Allow selected permissions for the Dev Spaces client. The redirect should return to your lab’s Dev Spaces address.

  3. If Dev Spaces asks whether you trust the repository, confirm Continue for fjcloud/go-app-template. This starts workspace creation.

If the factory reports Devfile hasn’t been resolved in the last 20 seconds, use Click to try again. Keep the repository’s devfile; do not choose Continue with default devfile.

  1. The launch URL selects OpenCode automatically. If a Create Workspace form appears, confirm OpenCode under AI Provider. This injects the CLI at start; you do not install it yourself. You will see a progress screen:

    Starting workspace...
Pulling universal developer image...
Injecting OpenCode...
Running postStart commands...
  ✓ Installing the ephemeral Git client

    Allow 2–5 minutes with cached images; the first start can take up to 15 minutes. Storage and the persistent home still need initialization. The cache wait above permits 10 minutes before launch. Keep the start screen open; do not create extra workspaces while one is starting. A timeout or an error in Events is a failure to inspect, not proof that the IDE is ready.

  2. When the workspace is ready, a VS Code-like editor opens in the browser. You will see:

    • A file explorer on the left

    • A terminal at the bottom

    • OpenCode available on PATH (injected by Dev Spaces, not by the template)

      Do not sign in to GitHub Copilot. Che Code ships Copilot as a built-in; the platform disables it. Do not install Continue. Use OpenCode in the terminal to call DeepSeek-V4 Pro.

If the editor opens in Restricted Mode, open Manage Workspace Trust, trust this repository, and confirm. The IDE may reload before its terminal becomes available.

Open the terminal inside Dev Spaces

In the browser editor’s top menu, choose Terminal → New Terminal. A shell opens in the bottom panel. If the menu is collapsed, use the editor’s main menu or Ctrl+Shift+P, then run Terminal: Create New Terminal. This is the Dev Spaces terminal; the WeTTY terminal beside this guide is still the bastion.

Run developer commands here, in $PROJECT_SOURCE. Shell blocks go into this terminal; natural-language prompt blocks go into OpenCode after it starts.

Check your scoped CLI access

The platform injects a separate developer kubeconfig into the workspace. Browser SSO and CLI access are separate; you do not paste an administrator token into the terminal or OpenCode.

Run inside Dev Spaces, not in the bastion: open Terminal → New Terminal in the browser editor and use the project directory ($PROJECT_SOURCE). Sign in to the Dev Spaces website as dev; its terminal receives a separate, limited workshop-developer service account for CLI commands.

 
# Show the CLI identity actually used by this terminal.
oc whoami
# Expect yes: the scoped identity can start application builds.
oc auth can-i create pipelineruns -n "${APP_NAME}-build"
# Expect yes: this identity can deploy in the application project.
oc auth can-i create deployments -n "${APP_NAME}-dev"
# Expect no: the developer has no permission to run privileged build pods.
oc auth can-i use scc/privileged -n "${APP_NAME}-build"

Expect the workshop-developer service account, then yes, yes, and no. The final no is intentional: OpenCode must not grant SCCs or use privileged containers. If build/deploy access is missing, ask the facilitator to rerun scripts/prepare-developer.py and restart the workspace. Keep the scoped identity; an administrator login is not a workaround.

The template also includes a local-only browser component for acceptance tests. OpenCode prepares it with npm ci && npm run setup. No system-package installation is needed in the developer container. The generated app remains a Go application.

  1. Check the project model configuration against the platform. The template’s opencode.json wins over the platform file; both should pin DeepSeek through MaaS. The following also updates older workspaces when needed. This file contains environment references; it contains no key. From the workspace terminal:

    Run inside Dev Spaces, not in the bastion: open Terminal → New Terminal in the browser editor and use the project directory ($PROJECT_SOURCE). Sign in to the Dev Spaces website as dev; its terminal receives a separate, limited workshop-developer service account for CLI commands.

    		 
# Use the cloned project directory inside Dev Spaces.
cd "${PROJECT_SOURCE}"
# Align the project’s model configuration with the injected platform configuration; it
# contains environment references, not a key.
cp "${XDG_CONFIG_HOME:-$HOME/.config}/opencode/opencode.json" opencode.json
# Commit only when the injected configuration differs from the template.
if ! git diff --quiet HEAD -- opencode.json; then
  # Stage only the intended model-configuration update.
  git add opencode.json
  # Commit the configuration change using the workshop developer identity.
  git -c user.name="Workshop Developer" -c user.email="dev@workshop.local" \
    commit -m "Use DeepSeek through the workshop MaaS gateway"
fi

Check the workspace identity in the UI
